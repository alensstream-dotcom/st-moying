# 墨影

个人自用的 SillyTavern 扩展。

## 安装

放进 `SillyTavern/data/<用户名>/extensions/`，或在扩展管理页填入本仓库地址。

## 更新

扩展管理页点「更新」。

## 这一版改了四个人物一致性问题

年龄、素材库开关都能在「设置 → 自动 tag → 素材库」里调，不用改代码。

1. **年龄段不再糊成一片、也不再画成老太太**：角色档案多了「年龄段」字段（child / teenager / young adult /
   mature female 四档，老妇、老婆婆并入成熟档，不再单开 old 档）。建档时必须同时写骨架词（身高、骨架、体型轮廓），
   因为只写一个年龄词压不住画风。档案页可以手动改；AI 改年龄会连骨架一起改。
   素材库的候选也按年龄段区分，同楼里四个年龄段画成同一个年纪的情况不会再出现。
   成熟档的骨架词里也不再叠 wrinkles / aged，否则一律画成老太太。
2. **同人骨相终于进得来，而且能按外形精确还原**：以前「注入人物外貌候选」默认关，同人条目永远排在
   脸型/体型后面挤不进去。现在默认开；正文点名作品名或角色名时那条同人**直接排第一**。
   更要紧的是外形：正文把角色写成「银白长发、紫瞳、尖耳」这种具体样子、而你库里正好有一条逐项对得上时，
   那条会被标「外形重合」压到第一位，提示词要求照抄它、不许再自己编一张脸。
   同一个判定也作用在已建档角色上——正文外形与某份档案对得上，直接点名「这段就是她」，不重复建档。
   想稳中还是把姓名写进正文，别指望外形词。
3. **同职业不再撞衫**：服装召回会在同分之间摇号（同一楼内固定，换楼换一批），提示词里也加了
   「不同的人不许穿同一件」和按廓形区分的硬要求。素材库补了 60 条廓形差别明显的款式，
   覆盖家居/运动/制服/礼服/日常/内衣/袜鞋，不只在职场装上堆。
   同人库另补 96 条近十年的游戏/番剧女角骨相，不再只有老作品。
4. **该特写就特写**：新增景别判据。正文写到阴蒂/穴口/乳头/手指/唇眼时该给 close-up，
   写到胸/腰臀时该给 upper body 或 cowboy shot，只有交代位置关系时才用 full body。
   给了远景但正文明明在写某个部位时，插件会判「景别过远」并重试收紧。

### 景别参照表

| 正文正在写的东西 | 该用的景别 | 常见错法 |
|---|---|---|
| 阴蒂、穴口、插入处 | close-up / lower body | 拍全身，部位只有一个点大 |
| 乳头、乳晕、乳房形状 | close-up / upper body | 拍全身 |
| 表情、眼神、唇、咬唇 | close-up | 拍全身 |
| 手指、抓握、指甲、握紧 | close-up | 拍全身 |
| 腰、臀、大腿根、胯部动作 | cowboy shot / lower body | 拍全身 |
| 姿势与两个人怎么接触、谁在上面 | full body 或 medium | — |
| 房间、站位、谁在门口 | full body / wide shot | 只剩脸，看不出空间关系 |

判据是**这一句的看点在哪一层**：看点是一个具体部位就收到那一层，整楼的图不许全在远景。
收景别时要把 body / 全身相关的 tag 一起收掉（否则模型还是按全身构图），
特写也别把眼睛裁出镜头。现在远景不会再被当成「有效构图」放过去。

## 这一版改的是画面准不准

上一版把人物固定住了，这一版解决「固定住了却画不对」：

1. **画面里该有谁、该有什么东西**：提示词里加了一道取景取舍。动作的施受双方、接触点本身、
   撑住动作的道具与它的落点，三样必须进画面；环境器物、背景闲人、远处的服饰细节可以省掉。
   漏人的代价不对称——两个男的一个女的只剩一个男的，肉棒就只能长在一个人身上；
   双人戏只剩一个女的就直接变成自慰。人塞不下就退景别、把人降成局部身位（手、腰胯、后背），
   不许删人；人数按画面里的身体数，不按有没有露脸。
2. **道具必须带落点**：毛笔在阴部写字，就写 `brush on pussy`，不许一手 `brush` 一手 `pussy`
   各飘一个 tag——分开写模型只会画一支支着的毛笔和一个裸体。道具、接触、方向都绑成词组落。
3. **先概括再写 tag，但不写多**：落 tag 前先用一句话说清「谁·用什么·在哪个部位·做什么·对方什么反应」，
   这句写不出来的格子不许画。tag 控制在 25～40 个，同一个意思不重复，形容词不叠三层，
   只留在画面上有形状的东西。写得多不等于写得准，塞满反而互相稀释。
4. **衣服不再乱飘**：新增跨楼服装账本。每楼把每个人「穿着什么、脱到哪一步」记在楼层里，
   下一楼直接注入成【服装现状】并当作既成事实——当前楼没写衣着就照抄，不再每层从零挑一套。
   同一楼内更不会换，脱离源就是「每层随机挑」。
5. **半脱固定成独立状态**：露肩、露背、露臀、掀裙写成 off shoulder / slipped down / pulled aside /
   skirt lifted / clothes around waist，衣服留在身上被画出来。只写 nude 会变光人，只写整套衣服又变没脱。
   账本里有半脱却画成全裸、账本里已经脱了又穿回整身，都会被判错并重试。

服装账本跟着楼层走，删楼或换 swipe 会自然失效；角色档案里的 outfit 仍是「她的常态衣橱」，
两者分工是「这场戏此刻穿到哪」对「她平时穿什么」。

## 被渠道拦、被截断的时候

先说清管辖范围：**破限挡位与「破限附加词」只作用于出图这条副 API 请求，不进正文生成**。
正文是 SillyTavern 主 API 生成的，插件塞不进任何提示词——正文被拦时调挡位没有用，那是渠道层的事。

能管的是出图请求。两件事分开说。

**一、被拦。** 拦截不认授权话术：过滤查的是请求与响应**文本本身**，提示词越露骨越容易被整条掐掉。
所以：

1. 拦截变成可判定的事：`finish_reason=content_filter`、空回复、或一段「抱歉，这段内容…」的客气话，
   都会被单独定性成「被渠道内容过滤拦下」，不再混在「解析失败」里。
2. 命中就降载重试：下一次改发兼容版——系统提示里的露骨示例词换成中性占位
   （`brush on <部位>`、`液体 on <部位>`），思考块压到 5 行并只保留最小结构。字段值本身不变。
3. 平时就少露骨：`<thinking>` 里改用英文 tag 短词描述身体与接触，不写中文长句。

真正被拦死了（连兼容版都过不去），出路只有换一个宽一点的渠道，或者把出图请求指到另一个模型上。

**二、被截断。** 「JSON 未闭合（差 6 个收尾括号）」说明输出被腰斩在写某张图的中途。旧版整份丢掉重发，
可重试只是让它「写短点」——图数不减，输出的主体成本没降，照样在同一处被切，于是反复失败。现在：

1. **先救，不重发**：从后往前找第一个还能闭合的位置，把尾巴补成合法 JSON。已经写完的那几张图
   是好的，救回几张就发几张，比整楼一张都没有强。
2. **救不动才重试，并且这次砍图数**：本楼压到最少张数（没设下限就压到 1），先保证交得出完整 JSON。
   少的那张回头再补，比整楼空白容易得多。

顺带说一句：**破限附加词恢复叠加**。它和档位是叠加关系（档位在前、附加词在后），留空时用内置默认那段；
选「关闭」只发附加词。上一版把它整段吃掉了，所以「开到极限也没用」——真正在起作用的那份根本没发出去。
